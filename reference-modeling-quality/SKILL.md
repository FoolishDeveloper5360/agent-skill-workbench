# 参考驱动的三维建模与质量闭环

目标：交付与参考形体相符、真实可编辑、可检查和可恢复的模型，而不是只在一个角度好看的图像。不要用部件齐全、面数很多或未经定义的“相似度 90%”代替质量证据。

执行前确认有可用的 Blender 操作途径、参考图读取能力和可写入位置。本技能提供流程与清单工具，不提供建模执行连接器；缺少能力时说明具体缺项，不声称已完成未执行的建模或检查。

## 建模前告知与单图确认

执行顺序：先读取素材并完成下文的范围确定与必要能力检查，再制作推断方案；单图方案获确认且建模所需能力可用后，才进入建模。参考分析和能力检查可交错进行，不能把章节排列理解成先画方案、后确定尺寸与用途。

开始执行建模前，必须向用户简要说明参考图要求，并结合实际素材如实说明可还原范围、缺失信息及推断部分，不能只依赖用户自行阅读 README：图片需可读取且主体轮廓与主要结构清楚，无固定分辨率或完整多视图要求；推荐同一对象、版本和状态的多角度图及关键细节近景。指出模糊、遮挡、裁切和视图冲突的具体影响。仅凭图片通常不能确定真实尺度；精确尺寸、单位、安装点和公差需有可靠依据，不承诺无证据支持的还原度。

按实际视角覆盖判断信息量，不按附件数量判断：重复图、同角度裁切和放大图不解除单图关卡，Agent 自己生成的推断图也不算新增真实参考。单张多视图拼图仍须展示对其缺失部分的推断方案供确认；若已覆盖所需方向，不凭空编造缺失视角，可整理已有视图并标注剩余结构假设供确认。没有可读参考时先说明缺项，不能声称已完成参考分析。

用户只有一张参考图时，以下是建模前的必经关卡：

1. 读取原图，区分可见事实与推断，列出缺失视角和关键结构假设。
2. 先制作并展示其他视图的二维推断图或示意图，覆盖关键缺失方向（如侧面、背面，必要时顶面），保持各视图结构与比例一致。明确标注“推断方案，非真实参考”，解释不确定的深度、背面、连接等设计；不能只用一句“其余部分自行推断”代替可供审阅的视图。
   展示前实际查看推断图，核对原图可见轮廓、用户尺寸约束及各视图的零件数量、位置、连接和比例；生成成功不等于方案正确。无法消除的歧义标出并提供可选方案，不把明显互相矛盾的图交给用户笼统确认。
3. 请求用户确认已展示的具体方案，然后等待。尚未展示方案时的建模授权、未回复或等待超时均不视为确认；确认前不得开始三维建模，包括粗模，也不能先建模型再渲染视图补办确认。可以继续环境检查与参考分析。
4. 用户要求修改时先更新推断图，再取得确认。记录获确认的方案版本及关键假设后才进入建模；后续实质改变已确认的推断结构时，先展示变更并重新确认。

确认必须能对应唯一的方案版本：记录图文件、关键假设、用户确认内容及其消息标识或时间（环境可取得时）。用户在明确展示的唯一方案后回复“按这个做”可作为确认；多个候选方案未选定、只确认部分视图或同时提出结构修改时，不能当作完整确认。已确认文件不得原地替换；新版本保留旧版本及确认关系。恢复任务时复用可核对的确认记录，不重复索要相同确认，也不凭不完整记忆假定已确认。

建模中收到新参考或尺寸要求时，先核对是否与方案冲突；影响轮廓、深度、关键连接或安装点的变化须暂停受影响的建模，更新方案并确认。为符合既定方案而修复网格、调整拓扑或提高对照精度不需重新确认。不得用用户确认覆盖原图事实或硬性尺寸冲突，冲突应明确说明并解决。

推断图可用当前可用的图像生成或二维绘图能力制作，不强制指定服务。无法制作或展示时必须说明能力缺项，请求补充参考视图或必要工具，不得虚构已展示的图或跳过关卡。用户确认仅表示接受方案，不把推断转为真实观察或已验证事实。

## 前置能力检查

由 Agent 在建模前完成，复用当前环境已有的有效检查结果，不让用户逐项配置或运行命令：

- 确认能读取本技能的参考文档与清单脚本、查看用户提供的参考图；修改已有模型时检查源工程和依赖是否可读。图片路径存在不等于已查看图片内容。
- 确认 Blender 的实际操作途径及版本，并具备保存、重新打开源工程、生成和查看检查图的能力。可使用本地脚本或现有连接器，不指定某一种工具；找到可执行文件不等于操作已验证。需要试运行时使用独立临时工程，不改动用户源文件。确认前的试运行只用于通用能力验证，不得制作任务对象或以环境检查名义提前建粗模。单图任务还须检查二维推断图的制作、查看与向用户展示能力。
- 确认已授权的成果目录可写入、读回并适合保留检查点，以及可调用 Python 3.8+ 执行标准库清单脚本。临时目录仅用于试运行，不能代替成果保存位置。
- 按交付要求检查附加能力：GLB 导出与干净场景回读、外部依赖读取、绑定或动画检查。静态任务不要求动画工具；已有 Blender 回读途径时不额外要求查看器。检查点中的云端占位文件、链接或重解析点按[保存及清单工具说明](references/checkpoint-delivery.md)处理。
- 必要能力缺失时说明受影响的步骤和最小补充条件；可继续读取参考与梳理约束，但不将未执行的建模或检查记为通过。软件安装、连接器配置和外部上传不因本检查自动获得授权。

## 减少用户操作

- 自行检查已有工具、直接读取附件或已提供路径，不要求用户重复整理素材、抄写环境信息或运行本可由 Agent 执行的命令。能力缺失时一次说明最小必要的配置，复用现有环境，不擅自安装软件。
- 优先按已给出的用途、尺寸和格式执行；不影响结果的选择自行处理并简述假设，仅在关键约束冲突或缺失会实质影响结果时提问，不逐项发问。单图任务仍须完成上述推断视图确认，不因减少用户操作而省略。
- 当前项目已获授权且适合保留成果时，自动建立独立版本的 `checkpoints/` 子目录保存，无需再次询问同一保存权限。若只有临时目录或无可用保存位置，再请求最小必要信息。
- 由 Agent 完成重开源工程、清单生成及校验。脚本路径相对于本技能目录解析，使用当前可用的 Python，不要求用户切换工作目录或复制命令。

## 开始前确定范围

- 读取全部参考图片和用户约束，不只挑两个方便的视角。列出各图的可见区域、遮挡、透视、关键轮廓、负空间、连接方式及不确定部分；区分“观察到”“尺寸指定”“推断”。
- 确定对象类型、用途、交付格式、是否需绑定或动画、尺寸单位和预算。尺寸缺失时可做比例重建，明确真实尺度未知，不编造精确尺寸。
- 将用户指定的外包围盒、局部尺寸、插槽/安装点坐标及公差列为独立约束，记录坐标系、原点和单位。约束冲突先指出，不以完成后的全局缩放掩盖错误。
- 在原文件副本或新版本工作；未经要求不覆盖已批准版本。只使用任务授权的输入与保存位置；本技能不授予发布、安装或第三方上传权限。

## 建模路径

进入本阶段前核对：范围与硬性约束无未解决冲突，必要能力和保存位置可用，单图任务的当前方案有明确确认记录。将原始参考、已确认推断图和尺寸约束一起作为建模依据；粗模先对照原始可见视角与已确认补充视图，通过主轮廓、深度和结构关系检查后再细化。若发现方案本身不可同时满足各视图或尺寸，回到方案修订与确认，不在三维模型中悄悄改设计。

1. 先做主轮廓和比例，再做标志性形体，最后细节。按参考视角设置可复现相机；透视参考先匹配投影，不把透视缩短直接当作真实尺寸。
2. 对识别度高的重复部件，先做一个有正确截面、曲率、厚度和连接的样件，并与近景参考比较，再复制、阵列或实例化。不要批量复制错误模板。
3. 硬表面：用真实实体/壳体、合理分件、倒角和接缝建形。需要厚度的板件必须有内外表面及边缘连接；双面材质不等于厚度。管线、铰链、支架须在合理安装点连接，不能悬空穿插。细节优先服务轮廓、负空间与结构关系。
4. 有机对象：改用整体体块、解剖/生长结构、雕刻、重拓扑和必要的置换/法线烘焙；动画资产检查变形拓扑。不把硬表面板件拼装或“一律封闭加厚”强加到毛发、叶片或有意开放的表面。
5. 保持 Blender 源工程可编辑：有意义的对象/集合命名，保留必要的修改器、实例源、材质与重建参数。交付需要时在导出副本应用修改器，而非破坏唯一源文件。
6. 纹理不能遮掩错误几何。投影贴图逐面检查，侧面/背面用合适的展开或重新投影，避免正面图被拉长包到侧面。不要让图像平面冒充用户要求的三维实体。

## 双重质量关卡

按 [references/quality-gates.md](references/quality-gates.md) 检查，技术通过和视觉通过分别记录。

- 每轮都对照关键轮廓、主要比例、负空间、关键零件位置和结构连接；检查全部已提供参考视角。用相同投影/构图的对照图或掩膜叠加定位差异，不能用不同角度的漂亮渲染替代比较。
- 尺寸和安装点在最终求值几何及统一坐标系下复核。检查厚度、背面、法线、接触/穿插、UV 与依赖文件。标明哪些检查没有做。
- 修复最影响外观的差异后再加微细节。若仍有显著误差，说明具体部位，不以面数或技术检查合格宣告高还原。
- 导出 GLB 后，在独立干净场景回读该文件，检查实际尺寸、朝向、材质、纹理、实例/修改器结果及必要的动画。源场景正确不保证导出正确。

## 先可恢复保存，再发预览

在向用户发送每个建模阶段的模型预览之前，先完成该版本的可恢复检查点，遵循 [references/checkpoint-delivery.md](references/checkpoint-delivery.md)。预览必须对应已保存的相同版本。建模前用于确认的二维推断图不是模型预览，不要求先创建 `.blend`；保存推断图及确认记录，并在建模后的检查点中作为设计依据保留。

- 检查点包含当前源工程、依赖纹理、存在时的重建代码/配置、当前导出、QA 证据和哈希清单。手工建模无需虚构全自动重建脚本，但必须有可打开的源工程及必要说明。
- 临时工作目录不是持久化交付。将检查点保存至当前任务已获授权且可验证持久保存的位置；验证写入和读取，记录真实保存凭证。不要要求某个固定账户或连接器。
- 用户指定保留的本地项目目录可作为保存位置；记录路径、重开源工程和清单验证结果，并说明仅本地保存。不要默认要求云端上传，也不把本地保存说成异地备份或永久保存保证。
- 若没有可用的持久保存渠道，保留本地成果，直接说明阻塞并请求最小必要的保存方式。不要声称已备份，不先发可能无法恢复的模型预览。
- 随交付简述：已完成内容、视觉偏差、技术检查范围、未验证项、源文件与导出位置。完整的运动干涉、工程强度和制造可行性不是静态视觉建模检查能保证的。

## 附带工具

使用 `python scripts/checkpoint_manifest.py create <检查点目录>` 生成清单，使用 `python scripts/checkpoint_manifest.py verify <检查点目录>` 复核文件大小与 SHA-256；工具仅需 Python 标准库。用法和局限见检查点参考。哈希一致只证明文件内容一致，不证明模型正确、保存持久或已获授权。
